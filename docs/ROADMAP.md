# LG 미니룸 구현 현황과 다음 Phase

## 현재 작업 순서 · 마이룸 진입과 루틴 재사용 (2026-11-26)

이번 단계는 ThinQ 화면을 재현한 프로젝트 웹에서 시작한다. 아래 번호는 이번 마이룸 작업 순서이며 제품 도트·방문자 체험의 기존 단계 번호는 각 절에 유지한다.

| Phase | 작업 | 완료 기준 |
|---|---|---|
| **1 · 진입 목적에 맞는 마이룸 (구현·브라우저 검증 완료)** | 하단 마이룸 탭에서 처음 들어와 체험용 기기를 준비하면 방 둘러보기로 돌아간다. 드림룸이나 친구 방에서 ‘내 방에 맞추기’로 왔으면 선택한 루틴의 기기 연결을 이어간다. | 빈 계정으로 두 경로를 각각 확인한다. 직접 입장하면 TV를 누르거나 배치를 편집할 수 있고, 루틴을 가져온 경우에는 내 TV를 고를 수 있다. 재방문 때 저장된 방과 루틴을 복원한다. |
| **2 · ThinQ 홈부터 루틴 재실행까지 (브라우저 검증 완료)** | 메뉴 → LG 미니룸 → 드림룸에서 TV 수집·배치 → TV 탭과 고양이 반응 → 영화 보기 → 내 방에 맞추기 → 내 TV 선택 → 저장을 하나의 브라우저 시나리오로 검증한다. | 320×568과 390×844 Chrome 터치 에뮬레이션에서 새로고침 후 하단 마이룸 → 내 루틴을 눌러 선택한 TV와 연결한 조명의 가상 반응을 확인한다. 드림룸 수집 TV와 마이룸 등록 기기는 별도로 유지된다. |
| **2B · 조명 한 대로 취침 루틴 (브라우저 검증 완료)** | 마이룸에서 조명과 침대를 직접 배치하고, 침대에서 조명 끄기를 미리 본 뒤 저장한다. | 320×568·390×844 Chrome 터치 에뮬레이션에서 조명 단독 체험과 등록 조명 한 대를 반환하는 테스트 계정을 각각 확인했다. 새로고침 후 침대와 내 루틴 양쪽에서 재생했고, 종료 후 조명 픽셀과 고양이 위치가 복원됐다. [취침 루틴 검사](../tests/thinq-bedtime-journey.cjs) |
| 3 · 현장 확인 (보류) | 방문자 QR 현장 운영과 iOS·Android 실물 폰에서의 사용자 관찰은 재개 결정 후 진행한다. | 재개 시 휴대폰에서 프로젝트 체험 화면에 도착하는지, 처음 온 사람이 루틴을 저장하고 다시 실행하는지 확인한다. |

Phase 1 검증 · Windows Chrome 터치 에뮬레이션 320×568·390×844에서 직접 입장 후 TV 터치·배치 편집, 드림룸의 청소 시간과 친구 방의 영화 보기 가져오기, 준비 화면에서 새로고침·취소, 기존 방과 저장 루틴 재열기를 확인했다. 등록 목록이 비었거나 기기가 아직 방에 없는 계정은 테스트 응답으로 재현했다. 실물 폰 관찰은 보류한다. [진입 경로 검사](../tests/thinq-navigation.cjs) · [친구 방](../tests/friend-room.cjs) · [방 안 가구와 TV](../tests/furniture-routines.cjs)

Phase 2 검증 · 320×568(동작 줄이기)과 390×844(일반 모션)의 독립된 빈 Chrome 브라우저에서 ThinQ 홈부터 시작했다. 직접 수집·배치한 TV를 탭하자 고양이가 반응했고, ‘영화 보기’를 누른 뒤 루틴 미리보기가 열렸다. 마이룸에서 침실 TV와 거실 조명 30%를 연결해 저장했다. 홈을 새로고침하고 가운데 마이룸 탭으로 돌아가 ‘내 루틴’에서 한 번 눌러 재생했다. 두 TV 화면과 조명 도트의 픽셀을 비교해 선택한 TV·조명의 반응과 종료 후 복원을 확인했다. 드림룸 수집품·배치도 일치했다. 재생 안내에 선택한 TV와 조명 설정을 함께 표시한다. [전체 사용자 흐름 테스트](../tests/thinq-movie-journey.cjs)

QR의 목적지는 현재 프로젝트 서버의 `/experience`이다. 제품 상세·미리보기·종료에서 첫 화면을 열면 같은 서버의 `/`로 이동한다. 일반 서버는 프로젝트 홈, 방문자 전용 서버는 체험 시작 화면을 연다. Phase 1·2는 브라우저에서 직접 시작할 수 있다.

## 현재 구현과 남은 기능

| 영역 | 현재 사용할 수 있는 기능 | 남은 구현 또는 결정 |
|---|---|---|
| 공간과 저장 | 모바일 세로 웹에서 드림룸·마이룸·읽기 전용 예시 친구 방을 연다. A·B·C 배치, 마지막 방·톤, 수집품과 저장 루틴은 브라우저에서 복원된다. 체험용 마이룸과 등록 목록 모드의 저장 공간을 구분한다. | ThinQ 앱 진입·복귀, 사용자 인증·계정별 동기화, QR 일회 체험 진입점. 현재 웹 에디터는 자동 저장하므로 QR 전용 세션 분리가 필요하다. |
| 꾸미기와 제품 반응 | 나무 벽·평마루·기본 1인용 소파, 드래그 배치, 네 방향 회전, 겹침 제한, 높이·복제·삭제·되돌리기, 이미지와 배치 파일 저장. 고양이가 선택한 TV·에어컨·공기청정기·워시타워·스타일러·냉장고·청소기 등에 반응한다. 침대 취침 모드에서는 고양이가 베개로 가서 이불을 덮는다. | 다른 생활 장면의 전후 상태 표시. 방 확장 조건과 사람·다른 동물 캐릭터는 후순위 결정이다. |

## 충돌하는 요구와 결정이 필요한 항목

- **방 기본형과 진입점.** 인수인계의 기본 침대·현관문보다 최근 사용자가 정한 평마루·1인용 소파를 적용한다. 침대는 서랍에서 추가한다. 외출 루틴은 문 복구 없이 현관 매트 등 배치 가능한 물건에 연결하는 안을 먼저 검토한다. 제품 상세도 현재 모바일 기준인 한 번 탭을 유지한다.
- **명칭과 저장 범위.** 원문 ‘통합 루틴 도감’의 수집·통합 목적을 현재 화면명 ‘루틴 인벤토리’에 반영한다. ‘내 루틴’은 등록 기기로 실행할 항목이다. 드림룸 소장과 마이룸 등록은 독립적으로 유지한다. 보유 가전을 드림룸 소장품으로도 지급할지는 미정이다.
- **QR.** 체험 웹 진입 QR, 현장 수집 QR, 새 가전의 기기 등록 QR은 용도가 다르다. 채택된 체험 웹은 로그인·DB 없이 시작하고 배치는 앱 계정으로 옮기지 않는다. 체험 안에서 가상 재생을 제공하며 후속 링크도 현재 프로젝트로 연결한다.
- **가져오기와 공개.** 친구 마이룸 → 내 마이룸, 내 드림룸 → 내 마이룸은 허용한다. 친구 드림룸 → 내 드림룸은 불가, 친구 마이룸 → 내 드림룸은 미정이다. 드림룸 상시 공개·마이룸 공개 선택은 기획 결정이다. 마이룸 초기 공개값, 보유 모델·실시간 상태·예약 시각 노출 범위, 제품 자체 복사 여부는 구현 전 결정한다.
- **실행 조건.** GPS 반경 제한은 메모와 본문이 다르다. 권한 거절·집 밖 예약을 포함해 결정하기 전에는 실행 조건으로 고정하지 않는다. 2in1 구성, 원격제어 사전 허용, 본체 시작 필요 여부는 실제 대상 모델에서 확인한다.
- **보상·제안.** 최대 99레벨, 마이룸 1시간당 1 Exp, 드림룸 2대 0.5 Exp와 추가 1대당 0.5 Exp, 튜토리얼 화폐 300은 원문 기록이다. 드림룸 시간 단위·냉장고 같은 상시 가전의 상한·계정 통합·도감 보상 개수는 미정이다. 꾸미기 100·130·150, 세트 할인 5~10%는 가격 예시다. 친구 루틴의 미보유 가전 쿠폰은 할인율·중복 발급 정책이 필요하고 내 드림룸 경로 지급은 미정이다.
- **보류·제외.** 공동 드림룸은 2,900원 기록과 출시·권한 미정 기록이 공존한다. 공식 큐레이터 방, AI 추천, 희소 등급·거래·강화·합성은 제안이다. 배경음악은 권리 확인이 선행된다. 3D 편집기 이식, 캐릭터끼리 실시간 상호작용, 가전 캐릭터 대결, 설문 유형별 추천은 이번 개발 범위에서 제외한다.

## 검증 근거

### 기존 제품 테스트 DB

2026-11-25 재확인. 현재 저장소 밖의 작업 산출물 `outputs/가전_도트_분석/제품_테스트.sqlite`에 9개 제품군이 이미 적재돼 있다. `products` 3,354행(서로 다른 모델명 3,263개)과 `sprite_examples` 31행(모델별 도트 표현 메모)이 있다. 원본 CSV 9개의 제품명·모델명·이미지 경로를 중복 포함 대조했고, 연결된 이미지 파일 3,354개의 SHA-256도 모두 일치했다. 이미지는 DB 외부 파일이며 내용이 다른 이미지는 3,065개다. 이 DB에는 바코드·기기 제어 권한·계정 및 사용자 루틴 테이블이 없다.

초기 카탈로그는 `data/products.sqlite`를 사용했다. 11월 25일 제품 도트 Phase 0에서 조회 원본을 이미지와 구성품이 들어 있는 `data/lg_appliances.db`로 전환했다. 드림룸에서 9개 제품군과 3,254개 모델을 검색·수집·배치할 수 있다. 기존 세탁기·가습기·로봇청소기 도트를 유지한다. 도트 Phase 1의 네 공기청정기는 기존 드림룸 C에서 제품 사진과 도형을 대조할 수 있다. 도트 Phase 2에서는 제습기 40개 모델의 외형 14종과 C룸 대표 전시를 구현하고 가습기·로봇청소기의 모델별 표시와 반응을 재검수했다. 도트 Phase 3에서 냉장고·세탁기·건조기의 대표 본체와 세트 구성을 구분했고, 미니워시 단품 9개를 실행 DB에서 제외했다. 도트 Phase 4에서 TV·무선청소기 955개 모델의 외형과 드림룸 세트별 구성 가전 선택·저장·재배치를 구현했다. 도트 Phase 5에서 전체 3,254개 모델의 렌더링과 C룸의 9개 제품군 배치·회전·선택·저장을 검수했다. 서로 다른 앞·뒤 도트 조합은 Phase 5의 286종에서 Phase 6의 290종으로 늘었다. 4A의 다음 작업은 실제 인식 공급자가 반환한 후보를 해당 모델에 매핑하는 것이다. 사용자별 방·루틴의 서버 저장은 별도 과제다.
