## 충돌하는 요구와 결정이 필요한 항목

- **방 기본형과 진입점.** 인수인계의 기본 침대·현관문보다 최근 사용자가 정한 평마루·1인용 소파를 적용한다. 침대는 서랍에서 추가한다. 외출 루틴은 문 복구 없이 현관 매트 등 배치 가능한 물건에 연결하는 안을 먼저 검토한다. 제품 상세도 현재 모바일 기준인 한 번 탭을 유지한다.
- **명칭과 저장 범위.** 원문 ‘통합 루틴 도감’의 수집·통합 목적을 현재 화면명 ‘루틴 인벤토리’에 반영한다. ‘내 루틴’은 등록 기기로 실행할 항목이다. 드림룸 소장과 마이룸 등록은 독립적으로 유지한다. 보유 가전을 드림룸 소장품으로도 지급할지는 미정이다.
- **QR.** 체험 웹 진입 QR, 현장 수집 QR, 새 가전의 기기 등록 QR은 용도가 다르다. 채택된 체험 웹은 로그인·DB 없이 시작하고 배치는 앱 계정으로 옮기지 않는다. 배치 후 추천까지만 볼지, 가상 재생까지 할지, 앱 설치 여부별 목적지는 미정이다.
- **가져오기와 공개.** 친구 마이룸 → 내 마이룸, 내 드림룸 → 내 마이룸은 허용한다. 친구 드림룸 → 내 드림룸은 불가, 친구 마이룸 → 내 드림룸은 미정이다. 드림룸 상시 공개·마이룸 공개 선택은 기획 결정이다. 마이룸 초기 공개값, 보유 모델·실시간 상태·예약 시각 노출 범위, 제품 자체 복사 여부는 구현 전 결정한다.
- **실행 조건.** GPS 반경 제한은 메모와 본문이 다르다. 권한 거절·집 밖 예약을 포함해 결정하기 전에는 실행 조건으로 고정하지 않는다. 2in1 구성, 원격제어 사전 허용, 본체 시작 필요 여부는 실제 대상 모델에서 확인한다.
- **보상·제안.** 최대 99레벨, 마이룸 1시간당 1 Exp, 드림룸 2대 0.5 Exp와 추가 1대당 0.5 Exp, 튜토리얼 화폐 300은 원문 기록이다. 드림룸 시간 단위·냉장고 같은 상시 가전의 상한·계정 통합·도감 보상 개수는 미정이다. 꾸미기 100·130·150, 세트 할인 5~10%는 가격 예시다. 친구 루틴의 미보유 가전 쿠폰은 할인율·중복 발급 정책이 필요하고 내 드림룸 경로 지급은 미정이다.
- **보류·제외.** 공동 드림룸은 2,900원 기록과 출시·권한 미정 기록이 공존한다. 공식 큐레이터 방, AI 추천, 희소 등급·거래·강화·합성은 제안이다. 배경음악은 권리 확인이 선행된다. 3D 편집기 이식, 캐릭터끼리 실시간 상호작용, 가전 캐릭터 대결, 설문 유형별 추천은 이번 개발 범위에서 제외한다.

## 신규 Phase와 통과 기준

| **4A · 제품 식별 연결** | 모델 담당자와 후보 모델 키·지원 범위·무후보·오류 응답을 합의한다. 바코드는 코드와 모델의 대응 자료가 필요하다. 모의 응답 개발은 앞 단계와 병행할 수 있다. | 닮은 모델·흐림·타사 제품·비가전·늦은 응답에서 잘못 지급하지 않고 수동 선택으로 복귀한다. 실제 샘플에서는 모델별 일치·오류·미판정을 구분한다. 원본 사진 처리 방침을 합의한다. |
| **4B · 상태와 즉시 실행** | 4A와 독립적으로 진행한다. 먼저 체험 장치로 명령·응답 화면을 만든다. 실제 연동은 승인 계정·지원 기기·모델별 기능이 확보된 뒤 읽기부터 검증한다. | **모형**은 LED·LCD 등 변경을 확인한다. **ThinQ**는 한 모델에서 목록 → 상태 조회 → 미리보기 중 명령 0건 → 명시적 실행 → 기기 상태 회신을 확인한다. 여러 기기 중 한 대만 응답할 때도 각각 표시한다. 증거를 모델·동작별로 분리한다. |

### 기존 제품 테스트 DB

2026-11-25 재확인. 현재 저장소 밖의 작업 산출물 `outputs/가전_도트_분석/제품_테스트.sqlite`에 9개 제품군이 이미 적재돼 있다. `products` 3,354행(서로 다른 모델명 3,263개)과 `sprite_examples` 31행(모델별 도트 표현 메모)이 있다. 원본 CSV 9개의 제품명·모델명·이미지 경로를 중복 포함 대조했고, 연결된 이미지 파일 3,354개의 SHA-256도 모두 일치했다. 이미지는 DB 외부 파일이며 내용이 다른 이미지는 3,065개다. 이 DB에는 바코드·기기 제어 권한·계정 및 사용자 루틴 테이블이 없다.

초기 카탈로그는 `data/products.sqlite`를 사용했다. 11월 25일 제품 도트 Phase 0에서 조회 원본을 이미지와 구성품이 들어 있는 `data/lg_appliances.db`로 전환했다. 드림룸에서 9개 제품군과 3,254개 모델을 검색·수집·배치할 수 있다. 기존 세탁기·가습기·로봇청소기 도트를 유지한다. 도트 Phase 1의 네 공기청정기는 기존 드림룸 C에서 제품 사진과 도형을 대조할 수 있다. 도트 Phase 2에서는 제습기 40개 모델의 외형 14종과 C룸 대표 전시를 구현하고 가습기·로봇청소기의 모델별 표시와 반응을 재검수했다. 도트 Phase 3에서 냉장고·세탁기·건조기의 대표 본체와 세트 구성을 구분했고, 미니워시 단품 9개를 실행 DB에서 제외했다. 도트 Phase 4에서 TV·무선청소기 955개 모델의 외형과 드림룸 세트별 구성 가전 선택·저장·재배치를 구현했다. 도트 Phase 5에서 전체 3,254개 모델의 렌더링과 C룸의 9개 제품군 배치·회전·선택·저장을 검수했다. 서로 다른 앞·뒤 도트 조합은 Phase 5의 286종에서 Phase 6의 290종으로 늘었다. 4A의 다음 작업은 실제 인식 공급자가 반환한 후보를 해당 모델에 매핑하는 것이다. 사용자별 방·루틴의 서버 저장은 별도 과제다.
