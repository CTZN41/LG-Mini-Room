## 이전 검수에서 실제로 따라간 경로

Windows용 Chrome을 스마트폰 세로 390×844 터치 화면으로 설정했다. 임시 회원 DB와 빈 브라우저에서 시작했다. 기존 회원 계정과 방에 테스트용 데이터를 넣지 않았다. 첫 브라우저는 카메라 모의 응답을 제어하기 위해 서비스 워커를 껐다. 재로그인한 두 번째 브라우저는 Chrome 기본 설정으로 실제 카메라를 다시 열었다.

1. QR 안내 화면에서 ‘이 기기에서 체험하기’를 누르고 회원가입했다. ThinQ 홈에서 디바이스·케어·메뉴를 오간 다음 하단 마이룸을 눌러 드림룸에 들어갔다.
2. 드림룸에서 카메라를 열고 취소했다. 다시 열어 TV 응답을 받은 뒤 인벤토리에 보관했다. 이때 방 배치는 그대로였다. 인벤토리에서 TV를 골라 직접 놓고 방 안의 TV를 터치했다. 이때 루틴 재생은 시작되지 않았고, 이어서 ‘영화 보기’를 눌렀을 때 재생·종료할 수 있었다.
3. 마이룸의 등록 가전 목록이 비어 있는 것을 확인했다. 같은 TV를 마이룸에도 등록하고 다시 스캔했다. 등록 목록에는 한 대만 남았다. 등록 직후 방 배치를 확인하고 인벤토리에서 직접 TV를 놓았다.
4. ‘직접 만들기’에서 침실 TV를 사용하는 ‘영화 준비’를 만들고 미리보기·저장·재생·종료했다. 기본 ‘영화 보기’도 같은 TV로 저장해 재생했다. 저장본에서 TV 기기 ID와 커튼 제외를 확인했다.
5. 실제 배포된 LG 카메라를 마이룸과 드림룸에서 각각 열었다. 앨범으로 시험용 냉장고 라벨을 넣고 인식·등록했다. 마이룸에서는 등록 가전으로 돌아왔고, 드림룸에서는 인벤토리 보관을 선택했다.
6. 첫 브라우저를 닫고 새 브라우저 세션에서 같은 계정으로 로그인했다. 저장한 ‘영화 준비’를 다시 눌렀을 때 침실 TV가 연결돼 있었다. 실제 카메라로 같은 냉장고를 다시 인식시켰을 때는 ‘이미 등록’ 안내가 나왔다.

TV는 미니룸의 응답 처리·중복 방지·배치를 반복 확인하기 위한 모의 카메라 응답을 사용했다. 냉장고는 실제 카메라 사이트의 앨범·문자 인식·등록 버튼과 반환값을 사용했다.

## 발견해서 수정한 문제

- **카메라에서 나오면 로그인 화면이 다시 열렸다.** 실제 카메라 사이트의 닫기 버튼으로 재현했다. 촬영을 시작한 탭에 방 주소와 회원 식별자를 기록하고, 복귀할 때 같은 계정임을 미니룸에서 확인한 뒤 방을 열도록 바꿨다. 촬영 요청 기록 없이 복귀 주소만 열면 안내를 표시한다. 현재 사용 중인 로컬 서버에서도 이 안내가 열리는 것을 확인했다.
- **마이룸에서 열어도 외부 카메라 버튼에는 ‘드림룸에 등록’이 쓰여 있다.** 마이룸 목록에 실제 저장 위치를 안내했다. 카메라 사이트의 버튼 자체는 두 방에서 여전히 문구가 같다.
- **모델명 인식과 등록 완료는 별개였다.** 시험 라벨에 `M876GBC472`만 넣으면 제품명까지 찾았지만 등록되지 않았다. `M876GBC472.AKOR`도 표시한 라벨로는 두 방 모두 등록됐다. 한 제품과 합성 라벨로 확인한 결과다.

| 2. 현재 제품으로 수집·배치 준비 · 4건 | `catalog-purifier-c`, `washer-models`, `collection-placement`, `placement-direction` | 현재 DB에서 개별 모델을 고른다. 제외한 세트는 목록에서 빠졌는지 별도로 확인한다. 인벤토리에서 고른 모델과 방에 놓인 제품이 같은지, 회전 후 새로고침해도 방향이 유지되는지 확인한다. |
| 3. 방 안의 터치·이동·충돌 · 4건 | `appliance-reactions`, `tv-interaction`, `robot-direction`, `placement-collision` | 2단계에서 검증한 제품을 놓고 화면에서 직접 조작한다. 누른 TV에 따라 고양이가 가까운 소파나 해당 TV 앞으로 가는지, 로봇이 화살표를 따르고 단차에 막히는지 본다. 실제로 겹치는 가구는 놓이지 않고, 허용된 배치는 저장되는지 확인한다. |
| 4. 영화 보기와 예시 친구 방 · 2건 | `thinq-movie-journey`, `friend-room` | 드림룸 TV와 읽기 전용 친구 방 소파에서 각각 영화를 발견한다. 침실 TV를 골라 저장·재실행하고, 미리보기 종료 뒤 TV·조명·고양이가 복원되는지 본다. 친구 방 배치와 기기 ID도 전후 비교한다. |
| 5. 전체 DB와 공개 목록 대조 · 4건 | `catalog-only`, `catalog-phase-five`, `catalog-phase-six`, `retired-sales` | 단품·제외 정책에서 예상 모델 목록을 만든 뒤 API·인벤토리·도트 표시와 대조한다. 누락·중복·제외 세트 재노출을 모델 코드로 표시한다. 총수 변경만으로 통과시키지 않는다. |

각 단계에서 같은 동작을 브라우저로 재현해 테스트 준비가 잘못된 경우와 사용자가 실제로 겪는 오류를 구분한다. 수정 후 해당 테스트를 다시 실행한다. 마지막에는 65개 전체를 재실행해 기존 통과분도 확인한다.

## 다시 실행하기

프로젝트 폴더의 PowerShell에서 실행한다. 각 명령은 임시 회원 DB를 만들어 사용한다.

```powershell
node tests/new-member-journey.cjs
node tests/batch-routines.cjs
node tests/thinq-bedtime-journey.cjs
```

실제 카메라 웹앱의 앨범 인식까지 포함하려면 다음 명령을 사용한다.

```powershell
$env:MINIROOM_LIVE_CAMERA = '1'
node tests/new-member-journey.cjs
Remove-Item Env:MINIROOM_LIVE_CAMERA
```

실제 휴대폰의 렌즈·초점·카메라 권한 팝업, 종이에 인쇄된 QR 촬영, 실물 ThinQ 가전 제어는 이번 검수 범위 밖이다.
